# Website Roadmap V2

Purpose: define the official restructuring roadmap for PKYDrip Website V2.

This roadmap starts after the audit phase. It does not redesign pages, rename URLs, change navigation, rewrite content, or move files. It defines the sequence for future work.

## Phase 0: Completed

Status: completed.

Completed audit and planning inputs:

- Site audit
- Site map
- Template audit
- Content mapping
- Navigation audit
- Internal link audit
- Image audit
- Site dashboard

Current findings:

- English site has 168 pages in the active planning scope.
- Current active layout count is approximately 48 template types.
- Products currently mix true product modules and system-level pages.
- Solutions currently mix application scenarios and system architecture topics.
- Resources are distributed across docs, guides, tools, downloads, internal, strategy, FAQ, and service pages.
- Landing pages are numerous and mostly appropriate as campaign pages outside core navigation.

## Phase 1: Information Architecture

Goal: finalize what belongs under Systems, Solutions, Products, Resources, and Landing.

Tasks:

- Finalize Systems.
- Finalize Solutions.
- Finalize Products.
- Finalize Resources.
- Finalize Landing structure.
- Decide canonical page for each duplicate system topic.
- Confirm that Applications gradually merge into Solutions.
- Define which legacy pages should remain, redirect later, or become support pages.
- Review Demonstration Systems / Showroom content strategy after Resources and proof content are reviewed.

Expected output:

- Stable site hierarchy.
- Canonical role assigned to every major page.
- No URL changes yet.

Decision rules:

- Systems explain engineering architecture.
- Solutions explain customer/application scenarios.
- Products explain real modules and product families.
- Resources support education, sizing, installation, documentation, and downloads.
- Landing pages serve campaign and partner conversion.
- Demonstration Systems / Showroom content can support proof, validation, and training, but Demo is not finalized as a primary public category yet.

## Phase 2: Template Consolidation

Goal: reduce template count and standardize layouts.

Tasks:

- Reduce template count from approximately 48 active types toward 6 major families.
- Standardize layouts for Home, System, Solution, Product, Resource, and Landing.
- Create reusable blocks for hero, architecture, applications, product recommendations, downloads, FAQ, CTA, and inquiry.
- Consolidate engineering-page variations.
- Consolidate landing-page variations after campaign needs are reviewed.
- Keep legacy fallback templates until content migration is safe.

Expected output:

- 6 major template families.
- Fewer custom one-off templates.
- Reusable components for system, solution, product, resource, and landing pages.

Goal: shift the website from engineering-first navigation to customer-problem-first navigation.

Tasks:

- Define major customer entry paths.
- Align homepage sections with customer groups.
- Ensure Systems, Solutions, Products, Resources, and Landing pages support different user types.
- Prevent homepage from becoming a technical category selector.

Customer paths:

Farm Owner:

Home
-> Solutions
-> Systems
-> Contact

Greenhouse Grower:

Home
-> Solutions
-> Systems
-> Products
-> Contact

System Integrator:

Home
-> Systems
-> Products
-> Resources
-> Contact

Distributor:

Home
-> Landing
-> Products
-> Contact

OEM Partner:

Home
-> Landing
-> Products
-> Contact

Expected output:

- A homepage and navigation strategy based on customer goals rather than internal engineering categories.

## Phase 3: Homepage Restructure

Goal: rebuild homepage using the V2 framework after information architecture and customer journey design are approved.

Homepage sections:

1. Hero
2. Who We Work With
3. What We Help You Build
4. Core Systems
5. Solutions
6. Why PKYDrip
7. Showroom
8. Contact

Tasks:

- Align homepage links with final Systems, Solutions, Products, and Resources.
- Ensure products support systems instead of dominating the page.
- Use customer-oriented language and visuals.
- Keep campaign pages out of main homepage flow unless they support current sales priorities.

Expected output:

- Homepage becomes the entry point into the V2 structure.

## Phase 4: System Architecture Integration

Goal: make Systems the core navigation concept.

Tasks:

- Make Systems the primary bridge between customer problems and product modules.
- Build internal links from Systems to Solutions.
- Build internal links from Systems to Products.
- Build internal links from Systems to Resources.
- Connect Landing pages back to the relevant System or Solution page.
- Establish canonical System pages for the four core Systems: irrigation control, fertigation, wireless irrigation, and solar pump irrigation.
- Treat Monitoring & Sensors as a supporting module and cross-system capability, not as a fifth primary System.

Expected output:

- Each System page becomes a strong hub.
- Product pages become supporting modules.
- Solution pages become customer/application entry points.

## Phase 5: Visual Upgrade

Goal: replace product-first imagery with customer-oriented visual explanation.

Tasks:

- Replace excessive isolated product images where they do not explain customer value.
- Introduce application photos.
- Introduce system diagrams.
- Introduce installation photos.
- Introduce dashboard and monitoring visuals as supporting visuals across relevant Systems and Products.
- Use product photos as supporting evidence instead of the main story.

Expected output:

- Homepage uses mostly application/system visuals.
- System pages use diagrams and application context.
- Product pages show application, installation, and product photos in balance.
- Landing pages use campaign-specific visuals and simple explanation graphics.

## Phase 6: Content Expansion

Goal: grow the site after the V2 structure is stable.

Tasks:

- Add engineering resources.
- Add solution guides.
- Add project examples.
- Add installation examples.
- Add downloadable technical documents.
- Add multilingual support later.

Expected output:

- Stronger SEO support.
- Better technical credibility.
- More useful entry points for farm owners, growers, integrators, distributors, and OEM partners.

## Governance Rules

- Do not create new custom templates unless they map to one of the six V2 families.
- Do not create new public category names such as Applications, Demo, Projects, or Services unless they are approved in the V2 framework.
- Use existing V2 categories whenever possible: Systems, Solutions, Products, Resources, and Landing.
- Do not create new product pages for system-level topics.
- Do not create new solution pages that duplicate existing system architecture pages.
- Every new landing page must connect back to a canonical System, Solution, Product, or Resource page.
- Every new product page must identify which System it supports.
- Every new resource page must identify related Systems, Solutions, or Products.
- Multilingual expansion should happen after English IA and templates are stable.

## Recommended Execution Order

1. Approve the V2 content classification.
2. Decide canonical System pages.
3. Define template requirements for each family.
4. Consolidate templates.
5. Rework homepage links and structure.
6. Strengthen internal links.
7. Upgrade visuals.
8. Expand resources and multilingual content.
