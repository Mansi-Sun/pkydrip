# PKYDrip Image Strategy

This document defines internal image usage rules for PKYDrip website pages.

## Core Principle

Avoid pages that only show isolated products.

Images should emphasize:

- Customer goals
- System outcomes
- Applications
- Installation context
- Control logic
- Product modules as supporting material

Product photos are important, but they should support a system story instead of replacing it.

## Homepage Image Mix

Recommended ratio:

- 80% application/system images
- 20% product images

Homepage image rules:

- Use farm, greenhouse, orchard, irrigation station, dashboard, and system architecture visuals.
- Avoid showing too many standalone controller boxes.
- Use custom system diagrams when real project photos are not yet available.

## System Page Image Mix

Recommended ratio:

- 50% system diagrams
- 30% application photos
- 20% product photos

System page image rules:

- Every system page should include at least one architecture diagram.
- Use application photos to show where the system is used.
- Use product photos only when explaining recommended modules.

## Product Page Image Mix

Recommended ratio:

- 40% application photos
- 30% installation photos
- 30% product photos

Product page image rules:

- Show the product in the context of irrigation, fertigation, wireless field control, or monitoring.
- Include installation or cabinet photos where possible.
- Include system integration diagrams when the product is part of a larger system.

## Solution Page Image Mix

Recommended ratio:

- 50% application photos
- 30% system diagrams
- 20% product or installation photos

Solution page image rules:

- Start with the customer's farm or project scenario.
- Use diagrams to explain the recommended architecture.
- Use product images only after the system logic is clear.

## Landing Page Image Mix

Recommended ratio:

- 60% application/system images
- 25% diagram or dashboard visuals
- 15% product photos

Landing page image rules:

- One clear hero visual is better than a mixed catalog collage.
- Match the image to the campaign promise.
- Partner/OEM pages should show project cooperation, system capability, and customization rather than retail product boxes.

## Downloads and Docs Image Rules

- Use diagrams and screenshots to explain technical concepts.
- Keep product photos minimal unless the document is a datasheet or product specification.
- Use consistent captions for diagrams.

## Recommended Visual Types

### System Diagrams

Use for:

- Irrigation control architecture
- Fertigation architecture
- Wireless field control
- Monitoring dashboard and records
- Solar pump irrigation configurations

### Application Photos

Use for:

- Greenhouse irrigation
- Orchard irrigation
- Open field irrigation
- Landscape irrigation
- Pump stations
- Remote field valves

### Installation Photos

Use for:

- Control cabinets
- Wiring
- Field valve installation
- Fertigation stations
- Sensor installation

### Product Photos

Use for:

- Controllers
- Gateways
- Dosing controllers
- Sensors
- Valve controllers
- Cabinet hardware

## Current Priority Fixes

1. Add or improve system diagrams for pages that only use product photos.
2. Replace isolated sensor images on monitoring system pages with dashboard/data/records visuals.
3. Use solar pump irrigation diagrams for solar pump pages until real project photos are available.
4. Move real project photos into future case study or project showcase pages.
5. Keep product catalogue images secondary to system and application visuals.

## Long-Term Asset Library

Create and maintain image folders by purpose:

```text
/images/system/
/images/application/
/images/installation/
/images/product/
/images/case-study/
/images/diagram/
/images/landing/
```

Each new image should have a clear purpose before it is added.
